# Daily Position Monitor — Market-Shock Alert Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-analyze currently-held swing positions on every trading day (not just at their scheduled exit date), and send an immediate Telegram alert when a held stock drops sharply intraday-to-close vs. its previous close — independent of whether the existing trailing-stop has been hit yet.

**Architecture:** `src/daily-position-monitor.src.js` already exists (trailing-stop recompute + alert), but it is **not wired into the live n8n workflow** — confirmed by grepping the live workflow export: zero nodes named `*Position*` exist among the deployed nodes (only stray code-comments mentioning the filename). This plan (a) adds a market-shock check to the existing dormant script, (b) regenerates its deploy bundle, and (c) wires it into the live n8n workflow as a new scheduled node running every trading day after market close (16:00 KST), per the file's own original design intent.

**Trader-perspective note:** the trailing-stop recompute alone is reactive and lags — it only fires once price has moved enough to justify raising the stop. A single violent down-day (broad market selloff, one of the many `[단일종목]` non-ETF picks gapping down) can hurt well before the trailing stop is anywhere close. A same-day-vs-previous-close shock check catches that risk on the very day it happens, which is what "다음주 시장 변동성" protection actually needs. Re-running the scanner's entry/regime score against held positions (option C offered earlier) was intentionally **not** chosen — [[swing-algo-sub-project-10-signal-weight-refit]] found the signal-weight AUC ~0.53 (near chance) for that scoring; reusing it to justify early exits on held positions isn't backed by evidence and would be over-engineering for a benefit we can't currently show.

**Tech Stack:** n8n Function node (plain JS, no npm deps — `this.helpers.httpRequest` only), existing `lib/naverClient.js` / `lib/telegramClient.js` / `lib/format.js` helpers, existing self-check convention (`scripts/verify_*.js`, plain `assert`-style, no test framework).

```javascript
// ===== 네이버 일봉 데이터 조회 =====
async function fetchDailyClose(code) {
  const kstNow = new Date(Date.now() + 9 * 3600000);
  const ed = kstNow.toISOString().slice(0, 10).replace(/-/g, '') + '235959';
  const sdDate = new Date(kstNow.getTime() - 10 * 24 * 3600000);
  const sd = sdDate.toISOString().slice(0, 10).replace(/-/g, '') + '000000';
  const items = await naver.fetchDaily(code, sd, ed);
  if (!items) return null;
  // 오름차순 정렬 기준 마지막 항목이 최신, 그 앞이 전일
  const latest = items[items.length - 1];
  const prev = items.length >= 2 ? items[items.length - 2] : null;
  return {
    close: Number(latest.closePrice || latest.close),
    high:  Number(latest.highPrice  || latest.high),
    low:   Number(latest.lowPrice   || latest.low),
    prevClose: prev ? Number(prev.closePrice || prev.close) : null,
  };
}
```

- [ ] **Step 1: Write the self-check script**

```javascript
/**
 * Self-check for the market-shock alert added to
 * src/daily-position-monitor.src.js (computeDayChangePct / SHOCK_DROP_THRESH gate).
 * Mirrors the exact day-change calculation so a future edit that breaks the
 * shock-detection logic fails this script.
 *
 * Run: node scripts/verify_position_monitor_shock_alert.js
 */
'use strict';

const SHOCK_DROP_THRESH = -0.05;

function computeDayChangePct(close, prevClose) {
  if (!prevClose || prevClose <= 0) return null;
  return (close - prevClose) / prevClose;
}

function main() {
  let failures = 0;
  const assertEq = (label, got, want) => {
    if (got !== want) { failures++; console.error(`FAIL ${label}: got ${got}, want ${want}`); }
  };

  // Case 1: exactly -5% -> trips the threshold (boundary is inclusive)
  {
    const changePct = computeDayChangePct(950, 1000);
    assertEq('exact -5% change value', changePct, -0.05);
    assertEq('exact -5% trips threshold', changePct <= SHOCK_DROP_THRESH, true);
  }

  // Case 2: -4.9% -> does not trip
  {
    const changePct = computeDayChangePct(951, 1000);
    assertEq('-4.9% does not trip threshold', changePct <= SHOCK_DROP_THRESH, false);
  }

  // Case 3: prevClose missing (null, e.g. brand-new listing) -> null, never trips
  {
    const changePct = computeDayChangePct(950, null);
    assertEq('missing prevClose returns null', changePct, null);
  }

  // Case 4: prevClose 0 (no usable prior bar) -> null, never trips
  {
    const changePct = computeDayChangePct(950, 0);
    assertEq('zero prevClose returns null', changePct, null);
  }

  // Case 5: up-day -> positive change, never trips
  {
    const changePct = computeDayChangePct(1100, 1000);
    assertEq('up-day change value', changePct, 0.1);
    assertEq('up-day does not trip threshold', changePct <= SHOCK_DROP_THRESH, false);
  }

  if (failures > 0) {
    console.error(`${failures} case(s) failed`);
    process.exit(1);
  }
  console.log('OK: market-shock alert day-change logic verified (5 cases).');
}

main();
```
